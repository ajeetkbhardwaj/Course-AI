## 1. Definition and Goal of Object Detection

**Object Detection** is a more challenging task than Object Recognition, which was covered previously [[00:22](http://www.youtube.com/watch?v=aEAN55ld-io&t=22)].

* **Recognition Goal:** Assumes the entire image contains only **one foreground object** and the goal is just to classify (label) the whole image (e.g., "cat") [[01:04](http://www.youtube.com/watch?v=aEAN55ld-io&t=64)].
* **Detection Goal [[01:17](http://www.youtube.com/watch?v=aEAN55ld-io&t=77)]:** In a general image containing  **multiple objects** , the task is two-fold:
  1. **Localization:** Find and draw a **bounding box** (rectangular window) around every object of interest [[01:29](http://www.youtube.com/watch?v=aEAN55ld-io&t=89)].
  2. **Classification:** Assign the correct **label** (class) to the object within that bounding box (e.g., Dog, Cat, Duck) [[01:34](http://www.youtube.com/watch?v=aEAN55ld-io&t=94)].
* **Summary:** The goal is to **find all bounding boxes and their corresponding labels** for all objects in the image [[02:10](http://www.youtube.com/watch?v=aEAN55ld-io&t=130)].

## 2. Limitations of the Sliding Window Approach

The traditional computer vision approach for detection was the **Sliding Window** method [[02:31](http://www.youtube.com/watch?v=aEAN55ld-io&t=151)].

1. **Process:** Take a fixed-size window, slide it across the entire image at every position, and pass the content of the window through a classifier to ask, "Is there an object here, and if so, what is it?" [[02:37](http://www.youtube.com/watch?v=aEAN55ld-io&t=157)].
2. **Problem:** This approach is computationally infeasible because objects appear at **many different scales and aspect ratios** [[03:51](http://www.youtube.com/watch?v=aEAN55ld-io&t=231)]. To capture all objects, the system would need to test a massive number of positions and scales of the window [[04:13](http://www.youtube.com/watch?v=aEAN55ld-io&t=253)], leading to excessive computation time [[04:26](http://www.youtube.com/watch?v=aEAN55ld-io&t=266)].

## 3. R-CNN: Region-based CNN (Original/Slow)

The R-CNN architecture was the first major breakthrough that replaced the exhaustive sliding window with a **wise subset of windows** [[05:55](http://www.youtube.com/watch?v=aEAN55ld-io&t=355)], but it was still known as the "slow" version [[08:49](http://www.youtube.com/watch?v=aEAN55ld-io&t=529)].

### A. The Region Proposal Step

The key idea is to look at a tiny, promising subset of potential object locations [[05:55](http://www.youtube.com/watch?v=aEAN55ld-io&t=355)]:

1. **Region Proposal Algorithm [[06:17](http://www.youtube.com/watch?v=aEAN55ld-io&t=377)]:** A separate, non-Deep Learning algorithm (e.g., Selective Search, used by R-CNN) is used to analyze the image and propose a set of regions that are **likely to contain an object** (often called "blobs" or Regions of Interest -  **RoI** ) [[06:43](http://www.youtube.com/watch?v=aEAN55ld-io&t=403)].
2. **Output:** For a given image, this algorithm typically generates about **2,000 such proposals** (bounding boxes) [[07:22](http://www.youtube.com/watch?v=aEAN55ld-io&t=442)].

### B. The R-CNN Workflow

The overall process involves four distinct components [[07:49](http://www.youtube.com/watch?v=aEAN55ld-io&t=469)]:

1. **Region Proposal:** Extract **$\sim$**2,000 Region Proposals from the input image [[07:16](http://www.youtube.com/watch?v=aEAN55ld-io&t=436)].
2. **Warping:** Each of the 2,000 proposed windows is **reshaped (warped)** to the fixed input size required by the CNN (e.g., **$227 \times 227$** for an AlexNet backbone) [[07:28](http://www.youtube.com/watch?v=aEAN55ld-io&t=448)].
3. **Feature Computation:** Each of the 2,000 warped images is passed **sequentially and independently** through the CNN to extract features [[08:36](http://www.youtube.com/watch?v=aEAN55ld-io&t=516)].
4. **Classification & Refinement:** The extracted features are passed to:
   * A **Support Vector Machine (SVM)** classifier for the final object classification [[08:56](http://www.youtube.com/watch?v=aEAN55ld-io&t=536)].
   * A **Bounding Box Regressor** to slightly adjust the proposed bounding box coordinates to make them more precise [[09:45](http://www.youtube.com/watch?v=aEAN55ld-io&t=585)].

### C. R-CNN Limitations

Despite its success, the original R-CNN suffered from significant drawbacks, primarily related to its speed and training complexity [[11:20](http://www.youtube.com/watch?v=aEAN55ld-io&t=680)]:

1. **Non-End-to-End Training [[10:14](http://www.youtube.com/watch?v=aEAN55ld-io&t=614)]:** The entire detection pipeline consists of **four separate, ad-hoc modules** that are trained independently:
   * Region Proposal algorithm (e.g., Selective Search).
   * CNN Feature Extractor (trained with Softmax).
   * SVM Classifier (trained with Hinge Loss).
   * Bounding Box Regressor (trained with Square Loss).
2. **Extremely Slow Inference [[11:37](http://www.youtube.com/watch?v=aEAN55ld-io&t=697)]:** The process is not real-time. It takes **47 seconds per image** (when using a VGGNet backbone) [[11:47](http://www.youtube.com/watch?v=aEAN55ld-io&t=707)].
3. **Inefficient Feature Computation [[12:45](http://www.youtube.com/watch?v=aEAN55ld-io&t=765)]:** The biggest bottleneck is that the CNN features are recomputed **2,000 times per image** (once for every region proposal). Since many of these proposed regions overlap, the CNN is repeatedly calculating the same features, wasting computational resources [[12:58](http://www.youtube.com/watch?v=aEAN55ld-io&t=778)].

This bottleneck led to the development of the next iteration,  **Fast R-CNN** , which aims to compute the CNN features **only once per image** [[13:17](http://www.youtube.com/watch?v=aEAN55ld-io&t=797)].
